# Pinned conversion toolchain for convert.sh (Python 3.11).
#   python3 -m venv .venv && .venv/bin/pip install -r requirements-convert.txt
#
# Same pins as the MoveNet recipe this replaces
# (apps/docs/examples/air-painting/convert-model/convert.sh), so both models in
# the repository were produced by one auditable toolchain.
#
# Why onnx stays at 1.17.0 here while requirements.txt carries 1.22.0:
# tf2onnx 1.16.1 is its last release (Feb 2024) and it cannot be resolved
# against a current onnx. pip reports two *independent* hard conflicts:
#
#   tf2onnx 1.16.1            depends on protobuf~=3.20
#   onnx >= 1.18              depends on protobuf>=4.25.1
#
#   tensorflow-cpu-aws 2.15.1 depends on ml-dtypes~=0.3.1
#   onnx 1.22.0               depends on ml_dtypes>=0.5.4
#
# So 1.17.0 is the highest onnx this toolchain can install, and neither
# conflict can be resolved without replacing tf2onnx or TensorFlow, which would
# invalidate the recorded graph digests this recipe exists to reproduce.
#
# The residual CVE-2025-51480 exposure is accepted deliberately and is bounded:
# this file is tooling only - never installed by the docs build, the example, or
# CI - and the only models it ever loads are the two hash-pinned Google
# artifacts that convert.sh downloads and verifies before use. That CVE needs an
# attacker-supplied model path, which this recipe never has. Anything that reads
# third-party or user-supplied ONNX uses requirements.txt (onnx 1.22.0).
pip==26.2
tf2onnx==1.16.1
tensorflow==2.15.1
onnx==1.17.0
numpy==1.26.4
