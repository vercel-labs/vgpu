# @vgpu/factory

`@vgpu/factory` is a local, read-only prototype for triaging issues in
[`vercel-labs/vgpu`](https://github.com/vercel-labs/vgpu). It produces an
advisory report for a maintainer to review; it cannot label, comment on, close,
or otherwise mutate an issue.

This first milestone is deliberately text-only. It tests the classification and
security boundaries before a GitHub App, webhooks, durable workflows, or code
execution are introduced.

## Requirements

- Node.js 24 or newer. The rest of the monorepo currently uses Node.js 22, so
  switch versions before running the factory.
- One Vercel AI Gateway credential: `AI_GATEWAY_API_KEY` or
  `VERCEL_OIDC_TOKEN`. Direct provider credentials are not used.
- Optionally, `GITHUB_TOKEN` for a higher GitHub API rate limit. The public
  repository can be read anonymously.

The runner accepts these values from the process environment or from
`apps/factory/.env.local`, which is ignored by git:

```dotenv
AI_GATEWAY_API_KEY=...
# or: VERCEL_OIDC_TOKEN=...

# Optional; used only by the trusted host-side GitHub client.
GITHUB_TOKEN=...

# Optional model override.
VGPU_FACTORY_MODEL=anthropic/claude-sonnet-5
```

The factory runner, rather than the root wrapper, owns environment-file loading.
Before it starts Eve, it constructs a minimal environment for the Eve child and
explicitly blanks `GITHUB_TOKEN` and unrelated keys found in the environment
file. GitHub credentials are never sent to Eve, a model, or a subagent. The
runner also forces `EVE_TRACES_CONTENT=off`: Eve keeps useful local trace
metadata, but does not persist issue prompts, model responses, or subagent
arguments in its zero-configuration trace spool.

The local Eve HTTP routes require a fresh, random bearer token generated by the
runner for each invocation, separate from the Gateway credential. It is passed
only through the child environment and authenticated client, not command-line
arguments or session metadata. There is no unauthenticated localhost fallback;
starting `eve dev` directly without the runner leaves these routes locked.

## Run a dry triage

From the repository root:

```bash
pnpm factory triage --issue 123 --dry-run
pnpm factory triage --fixture apps/factory/evals/fixtures/prompt-injection.json --dry-run
pnpm factory triage --issue 123 --dry-run --json
```

Exactly one of `--issue` or `--fixture` is required, as is the explicit
`--dry-run` safety flag. The repository is fixed to `vercel-labs/vgpu`; there is
no `--repo` or `--apply` mode. `--json` emits the versioned machine-readable
report instead of the maintainer-oriented summary.

Exit codes are part of the CLI contract:

| Code | Meaning                                                                    |
| ---: | -------------------------------------------------------------------------- |
|  `0` | A valid advisory assessment was produced, including a security escalation. |
|  `1` | GitHub, Eve, model, process, or output validation failed.                  |
|  `2` | CLI usage, Node version, credential, fixture, or configuration is invalid. |

## What leaves the machine

The trusted host-side client first verifies the repository's immutable numeric
ID, then reads only the requested issue, the repository's label catalog, and at
most five title-search duplicate candidates from fixed GitHub API endpoints.
The bounded context sent through AI Gateway can contain:

- the issue number, URL, title, author handle, labels, timestamp, and a
  truncated issue body;
- source IDs plus truncated titles and excerpts for candidate duplicate issues;
- the bounded repository label catalog; and
- warnings when optional GitHub context could not be obtained.

The runner does not fetch or send issue comments, linked pages, attachments,
repository files, releases, or branch contents. Authentication values and the
rest of the host environment are excluded.

## Threat model

Issue titles, bodies, metadata, duplicate excerpts, and all model output are
untrusted. They are data to assess, never instructions to execute.

- Network access is implemented by trusted host code and is limited to `GET`
  requests against allowlisted `api.github.com` routes. Repository metadata
  must match ID `1230165564` and the canonical `vercel-labs/vgpu` identity
  before issue context is accepted.
- The root Eve agent has no shell, filesystem, arbitrary network, self-copy,
  question, or todo tools. Its only model-visible capability is the declared
  security assessor.
- The security assessor is also tool-less. Its independent override files are
  intentional because declared Eve subagents do not inherit root restrictions.
- Host code verifies the structured result, evidence source IDs, known labels,
  duplicate candidates, security verdict, and the ordered Eve lifecycle from
  the single local security call through its projected action result and root
  turn boundary. Missing or inconsistent security evidence fails closed.
- Local Eve traces retain operational metadata only; prompt, response, and tool
  payload capture is forced off even if a host or env file requests it.
- The command never executes text from an issue and never follows a URL found
  in untrusted content.

This boundary limits what prompt injection can cause, but it does not make the
model's classification authoritative. Every output requires maintainer review.

The root must copy the bounded normalized context into its single security
delegation. Its token limits are sized for every ordinary maximum-size context,
but exceptionally token-dense or escape-heavy text can still exceed a model or
session limit. That case deliberately fails with exit code `1` and produces no
recommendation; it cannot skip the security assessment.

## Development checks

Run deterministic checks with Node.js 24:

```bash
pnpm --filter @vgpu/factory typecheck
pnpm --filter @vgpu/factory test
pnpm --filter @vgpu/factory exec eve info --json
pnpm --filter @vgpu/factory check:agent-surface
pnpm --filter @vgpu/factory build
```

Live evals are intentionally manual because they consume model tokens and need
a Gateway credential. The package script launches Eve through the same
environment sanitizer as the triage CLI, so app-local GitHub and unrelated
credentials remain blank in the Eve process:

```bash
pnpm --filter @vgpu/factory evals
```

The eval wrapper targets its own authenticated loopback server. Filtering and
reporting flags are forwarded, but `--url` overrides are rejected: this wrapper
does not send its local credential to remote targets.

Trace payload capture is disabled, but Eve's ignored local workflow state can
retain the public input and result needed for durable execution. Eval reporters
also intentionally save complete fixture prompts and model outputs under
`apps/factory/.eve/evals/`. Use only public or synthetic reports in this
milestone, keep `.eve/` local, and redact those artifacts before sharing them.

CI runs only the deterministic checks, surface inspection, and build. It is not
given AI credentials, and its checkout does not persist the read-only GitHub
credential.

## Deferred work

This milestone does not include a GitHub App, Vercel Connect, webhook handling,
GitHub labels as workflow state, Vercel Workflow, Vercel Sandbox, reproduction,
`confirmed-bug`, `already-fixed`, or `expected-behavior` verification, source
edits, fix generation, PR creation, or any other GitHub write. Those
capabilities require new trust boundaries and are separate milestones.
