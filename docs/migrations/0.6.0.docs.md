# Migrating to 0.6.0

This guide targets `0.6.0-rc.0`, the first candidate for `0.6.0`. Update `vgpu` and any
directly installed packages in its fixed release group to the same version:
`@vgpu/core`, `@vgpu/wgsl`, `@vgpu/wgsl-std`, `@vgpu/adapter-node`,
`@vgpu/adapter-mock`, `@vgpu/render` and the optional `@vgpu/native` companion.

```sh
npm install --save-exact vgpu@0.6.0-rc.0
# Only if the project already uses native generation:
npm install --save-dev --save-exact @vgpu/native@0.6.0-rc.0
```

The native companion remains beta with the same toolchain and platform qualifications as
`0.5.0`. Regenerate and verify native output with the matching version. No new native
configuration or generated Swift API migration is required by this candidate.

## From the previous stable release

For projects on `0.5.0`, apply the steps relevant to the APIs they use. Projects on an
older stable first apply the [0.5.0 migration](/migrations/0.5.0), then this guide.
This is a pre-1.0 release with compatibility changes; it is not a drop-in update for
every existing scene or frame callback.

### 1. Replace scene object and camera authoring

Geometry recipes, `geometries`, `degToRad`, `srgb`, geometry types, `group` and
`SceneNode` remain. Scene composition now supplies transforms, camera matrices and
instance data to application-owned shaders and draws.

| Previous export or usage | Replacement |
| --- | --- |
| `scene()` | `group()` as the root. |
| `mesh()`, `MeshNode` | A `group` or external world matrix, plus explicit `geometry()` and `draw()`. Use `instances()` and `instanceGeometry()` for repeated objects. |
| `SceneMaterial`, `UnlitMaterial`, `LambertMaterial`, `NormalMaterial`, `ShaderMaterial`, their lowercase factories and material option/value types | Application WGSL, pipeline options and named bindings. There is no replacement material object. |
| `AmbientLight`, `DirectionalLight`, their lowercase factories and option/value types | Application light data passed to the shader. |
| `PerspectiveCamera`, `perspectiveCamera` and their option/value types | `Lens`, `Pose`, `perspective()` and `viewMatrices()`. |
| `OrthographicCamera`, `orthographicCamera` and their option/value types | `orthographic(bounds, out)` and `viewMatrices()`. |
| `Camera`, `SceneCamera`, `CameraVec3` | `Pose`, `Lens`, `CameraMatrices`, and `Vec3Like` or `ArrayLike<number>`. |
| `OrbitControls`, `orbitControls` and their element/option/value types | Application input listeners, `orbitRig()`, `orbit()`, `pan()`, `dolly()`, `smoothRig()` and `rigPose()`. |
| `orbit(time, options)`, `OrbitOptions` | `composeMatrix()` for object animation. The new `orbit(rig, deltaYaw, deltaPitch, limits?)` changes a camera rig. |
| Other `SceneNodeKind` values | Only `"group"` remains; keep application classifications separately. |

#### Keep transforms independent of geometry and materials

Before:

```ts illustrative
const root = scene();
root.add(mesh(box(), normalMaterial(), { position: [1, 0, 0] }));
const model = orbit(time, { radius: 2, height: 0.5, speed: 0.3 });
```

After:

```ts
import { composeMatrix, group, instances } from "vgpu/scene";

const root = group();
const object = group({ position: [1, 0, 0] });
root.add(object);
const objects = instances({ capacity: 100 });
const id = objects.add();
objects.bindWorld(id, () => object.worldMatrix);
object.set({ position: [2, 0, 0] });
objects.syncWorlds();

const model = new Float32Array(16);
function animateObject(time: number) {
  const angle = time * 0.3;
  composeMatrix({
    position: [Math.cos(angle) * 2, 0.5, Math.sin(angle) * 2],
    rotation: [0, angle, 0],
  }, model);
}
```

`composeMatrix()` writes into reusable output; it does not allocate the old orbit matrix.
Keep radius, height and speed in application state, including a zero radius when intended.
Change borrowed node vectors through `.set()` rather than mutating them. Reparenting preserves
the local transform. `visible` remains metadata and does not suppress a draw or instance.
Nonzero quaternions are normalized; zero quaternions and non-finite node values throw
`VGPU-SCENE-VALUE`.

Instance capacity is fixed. Growing it requires a new collection and GPU bridge, copied
application data, restored world bindings and replacement handles/draws. Handles remain stable
only during an instance's lifetime; removal can move dense slots. Keep picking mappings in
application state and do not serialize `InstanceId` values.

External hierarchies can use `hierarchyOrder()` and `evaluateHierarchy()` with finite affine
local matrices. Rebuild the order after changing parents and fully evaluate after topology or
world-output replacement/reset. Dirty flags reduce matrix recomputation, not traversal, and
remain caller-owned. Physics with final world matrices can call `setWorlds()` directly.
If a bound `syncWorlds()` source throws, earlier results may already be copied: abort the frame
and repair/retry or unbind those sources before publishing.

#### Own camera state and repack camera uniforms

Before, a camera object carried projection and view state:

```ts illustrative
const camera = perspectiveCamera({ fov: 45, aspect, position: [2, 2, 3] });
camera.set({ aspect });
drawable.set({ camera: { viewProjection: camera.viewProjection } });
```

After, supply the lens, world pose and output matrices explicitly:

```ts
import { group, perspective, viewMatrices } from "vgpu/scene";

const eye = group({ position: [2, 2, 3] });
const lens = { fov: 45, near: 0.1, far: 100 };
const pose = { position: new Float32Array(3), quaternion: new Float32Array(4) };
const projection = new Float32Array(16);
const matrices = { view: new Float32Array(16), viewProjection: new Float32Array(16) };

function updateCamera(aspect: number) {
  eye.lookAt([0, 0, 0], [0, 1, 0]);
  pose.position.set(eye.worldPosition);
  pose.quaternion.set(eye.quaternion); // eye is unparented: its local pose is world space
  perspective(lens, aspect, projection);
  viewMatrices(pose, projection, matrices);
}
updateCamera(16 / 9);
```

Repeat `drawable.set({ camera: { viewProjection: matrices.viewProjection } })` after every
matrix update. Uniform `.set()` packs immediately; previous calls do not retain live matrix
arrays. The shader owns the resource name and binding location; scene reserves no bind group.

For a parented camera, preserve the full old world transform, including parent scale, by
inverting `cameraNode.worldMatrix` with `invertAffine()` and multiplying projection by view
with `multiplyMatrices()`. A `Pose` contains world position/quaternion only; copying a
parented node's local quaternion loses the parent transform. Zero scale is not invertible
and throws `VGPU-SPATIAL-SINGULAR`.

Choose the old defaults (`near: 0.1`, `far: 100`, `aspect: 1`) explicitly if required.
Perspective requires finite `0 < near < far`, positive finite aspect and FOV in degrees
strictly between 0 and 180. Replace infinite far planes with a finite distance. Orthographic
bounds require finite `left < right`, `bottom < top`, and `0 <= near < far`; formerly accepted
mirrored bounds now throw `VGPU-CAMERA-VALUE`. Supply your own projection to `viewMatrices()`
when a mirrored projection is intentional. Both helpers use right-handed −Z view space and
WebGPU depth 0..1.

For input, create independent goal/current rigs. Apply events to the goal; call
`smoothRig(current, goal, dt, { timeConstant })` with finite nonnegative seconds, then
`rigPose()`. Remove input listeners on teardown. Smoothing uses logarithmic distance,
returns the current rig, and has no epsilon snap or changed boolean. It no longer substitutes
1/60 for missing/non-finite `dt`; implement your own settling policy. A zero time constant
snaps even at zero `dt`; otherwise zero `dt` leaves the current state unchanged. The default
pitch range is ±(π/2−1e−4); pass explicit limits to retain the old ±(π/2−0.01) range.
`dolly()` changes distance; `zoom()` changes the lens.

#### Publish instance data before encoding its consumers

Import `instanceGeometry` from `vgpu/scene/gpu`; it borrows a live, non-instanced mesh from
the same GPU. Declare four world columns and all custom instance attributes in each consuming
vertex entry. A world matrix costs four attributes and 64 bytes per record, in addition to
custom 32-bit attributes. Respect device limits, the eight-buffer limit and 2048-byte stride;
split batches or reduce attributes/capacity on `VGPU-INSTANCE-LAYOUT`.

```ts illustrative
objects.syncWorlds(); // or objects.setWorlds(ids, finalWorlds)
const count = bridge.publish();
drawable.set({ camera: { viewProjection: matrices.viewProjection } });
frame(gpu, f => f.pass(screen, pass => pass.draw(drawable, { instances: count })));
```

`publish()` does not update camera/world sources and returns an explicit count, including zero.
Unchanged publication uploads no instance bytes; separate bridges track uploads independently.
Record the count explicitly in bundles and re-record when it changes. Publish before all passes
that consume those bytes. Do not rewrite a buffer while earlier consumers remain unsubmitted;
distinct per-pass contents require separate buffers. Later queue-ordered frames need no idle wait.

Destroying a bridge destroys its added buffer and composed wrapper, not the borrowed mesh.
Destroying the mesh invalidates dependent draws and bundles. Recreate the bridge/draw and
re-record bundles; raw buffer destruction outside the geometry lifecycle is not tracked.
Ordinary destroyed geometry now fails synchronously with `VGPU-MESH-LAYOUT-INVALID`; bridges
use `VGPU-INSTANCE-DESTROYED`.

WGSL can import `instanceWorldMatrix`, `transformPosition`, `transformDirection` and
`transformNormal` from `@vgpu/wgsl-std/scene`. They introduce no bindings. Use the complete
world/deformation transform: position uses w=1, direction w=0, and normals use normalized
inverse-transpose with reflection sign. Extreme ill-conditioned float32 inputs or backend
subnormal handling can lose direction/sign accuracy; the zero fallback has no epsilon or
symbolic-rank guarantee. See [Scene composition](/guides/scene-composition) for complete setups.

### 2. Choose shader entries and distinguish inputs from presentation

#### Pin shader entries when preserving the previous choice

With multiple entries of one stage, automatic selection now prefers `vs_main`, `fs_main`
or `cs_main`. A single entry can have any name; without the conventional name the first
entry still wins. If `0.5.0` selected an earlier nonconventional entry, name it explicitly:

```ts illustrative
draw(gpu, { shader, entry: { vertex: "previous_vertex", fragment: "previous_fragment" } });
compute(gpu, computeSource, { entry: "previous_kernel" });
effect(gpu, fragmentSource, { entry: { fragment: "previous_fragment" } });
```

Override only affected stages. Selection determines resources and vertex input layouts as well
as execution; compare pixels/readbacks and bind everything the chosen entry uses. Invalid names
or wrong stages throw `VGPU-ENTRY-INVALID`. Effects expose fragment selection only. For an effect
with custom vertices that must avoid `vs_main`, rename the unselected conventional function or
use `draw()` with explicit selections. Fragment-only effects retain the generated fullscreen vertex.

Runtime WGSL string compilation now discovers attributed compute entries, Unicode names and
WGSL whitespace correctly while ignoring comments. Its signature and shader passthrough are
unchanged; corrected metadata requires no new call shape.

#### Replace Surface input bindings with offscreen resources

Passing a `Surface` to a Draw, Effect or Compute binding now throws
`VGPU-SURFACE-NOT-BINDABLE`, both in constructor `set` options and later `.set()` calls.
The surface remains a render destination. Replace a sampled presentation workflow:

```ts illustrative
frame(gpu, f => {
  f.pass(screen, producer);
  consumer.set({ source: screen });
  f.pass(preview, consumer);
});
```

with an offscreen producer and final presentation:

```ts
import { effect, frame, init, surface, target } from "vgpu";

const gpu = await init();
const screen = surface(gpu, document.querySelector("canvas")!);
const intermediate = target(gpu, { size: screen.size });
const producer = effect(gpu, `
  @fragment fn main(@location(0) uv: vec2f) -> @location(0) vec4f {
    return vec4f(uv, 0.0, 1.0);
  }
`);
const consumer = effect(gpu, `
  @group(0) @binding(0) var source: texture_2d<f32>;
  @fragment fn main(@location(0) uv: vec2f) -> @location(0) vec4f {
    return textureLoad(source, vec2i(uv * vec2f(textureDimensions(source))), 0);
  }
`, { set: { source: intermediate } });
screen.onResize(({ width, height }) => intermediate.resize([width, height]));
await producer.compile(intermediate);
await consumer.compile(screen);
frame(gpu, f => {
  f.pass(intermediate, producer);
  f.pass(screen, consumer);
});
```

A bound `Target` follows attachment replacement after resize. An explicit `Texture` keeps that
identity: rebind it after replacement. Read intermediate results with
`intermediate.color.read({ mipLevel: 0, region: "all" })`. `surface.color` remains the current
presentation texture; retaining it does not extend its lifetime beyond presentation.

#### Opt into direct depth-tested canvas rendering when useful

Existing surfaces keep no depth attachment and one sample. Existing two-pass offscreen rendering
still works. For direct presentation, `surface(gpu, canvas, { depth: true, msaa: 4 })` adds
`depth24plus` and four samples. `depth` also accepts supported explicit depth-aspect formats;
`msaa: true` also means four samples. No `sampleCount` option is added.

`compile(surface)`, `compileSync(surface)`, Draw constructor `targets`, and bundle recording
can run outside frames using the configured color/depth/sample signature without acquiring a
canvas texture. They honor opt-in depth/MSAA; they are not limited to one sample or no depth.
When supplying an explicit signature, match the actual surface format and attachments; query
the preferred canvas format before creating a surface rather than assuming BGRA/RGBA. Draw
and replay canvas work inside `frame()` or `frameLoop()`.

`surface.depth` is owned and stable until replacement/disposal. MSAA color storage is private
and resolves into the single-sample `surface.color`. To sample depth, bind `surface.depth`
explicitly on a surface without `msaa` and rebind it in `onResize` after replacement. Resize
outside the frame, before encoding attachment consumers. Explicit and automatic layout/DPR
resizes notify listeners after committing replacements;
a listener failure does not undo the resize or prevent other notifications/old-attachment cleanup.
Synchronous allocation failure preserves the previous surface size and attachments. Recursive
resize during replacement notification throws `VGPU-SURFACE-RESIZE-REENTRANT`.

Direct canvas dimension writes between frames reconcile owned attachments before the next frame
callback without public resize notifications. The pass descriptor also reconciles later writes,
but mid-frame changes can invalidate attachments already encoded. Use explicit resize and rebind
when consumers retain depth. Offscreen targets remain useful for sampling, postprocessing,
history and readback; these additions require no rewrite of an existing offscreen workflow.

### 3. Prepare asynchronously, then encode frames synchronously

`compute()` now constructs a lazy pipeline. Call `await simulation.compile()` before rendering
when preparation must finish in advance; the promise rejects compilation failures and resolves
to the same object. `compileSync()` or first dispatch compiles synchronously. Native synchronous
creation failures now throw, and automatic reuse of a failed pipeline throws rather than silently
skipping work. An explicit compile retries. `compile()` after `compileSync()` waits for native
validation, including synchronous takeover of pending asynchronous compilation.

Move awaits out of `frame`, `frameLoop`, equivalent `FrameRunner` methods and compute-pass
callbacks. For example:

```ts illustrative
// Before
frame(gpu, async f => {
  await loadAssets();
  simulation.dispatch(64);
  f.pass(output, display);
});

// After
await loadAssets();
await simulation.compile();
frame(gpu, f => {
  f.computePass(pass => pass.dispatch(simulation, 64));
  f.pass(output, display);
});
```

`simulation.dispatch()` still submits independently, even inside a frame. Use `computePass()`
for ordered render/compute work in one frame submission and cancellation. Passes cannot nest;
do not retain the pass after its callback or submit/cancel before it ends. Dispatch counts must
be finite nonnegative integers within the granted device limit, and workgroup dimensions/product
must fit device limits. Request supported larger limits through `init({ requiredLimits })` or
reduce workgroups; defaults did not increase.

Inferred Promise/PromiseLike returns, unions containing them, and unresolved generic callback
returns fail typechecking. Concrete synchronous returns remain accepted and ignored. For a
forwarder whose contract ignores the result, accept `FrameLoopCallback` or `(frame: Frame) => void`
and pass the callback directly. Do not erase an async continuation with casts or wrappers.
Callbacks typed `void`, `unknown` or `any` can pass types but still throw
`VGPU-ASYNC-FRAME-CALLBACK` if they return a thenable. The open frame is canceled before implicit
submission, and a failing loop stops. Already submitted work and CPU-side continuations are not
rolled back; later encoding through that canceled frame fails with `VGPU-FRAME-CANCELED`.

#### Set each direct operation's uniform values before encoding it

Direct frame draws and dispatches now capture managed uniform values per operation:

```ts illustrative
frame(gpu, f => f.computePass(pass => {
  simulation.set({ dt: 0.01 });
  pass.dispatch(simulation, 64); // captures 0.01
  simulation.set({ dt: 0.02 });
  pass.dispatch(simulation, 64); // captures 0.02
}));
```

If the old application expected the last update to affect every operation, set that common value
before encoding them. Capture covers JS-owned uniform bindings and `uniforms()` used as uniforms.
Storage, shared uniforms adopted as storage, raw buffers, claimed groups and render bundles retain
live buffer contents. Use separate resources for distinct bundle/raw-buffer values in one
submission. Host writes and CPU mutations are outside frame cancellation.

Upload deferral preserves these semantics: `.set()` still validates and packs immediately,
one-shot work uploads pending values when needed, and exposed stable raw buffers are flushed
before exposure and continue receiving immediate updates. No consumer flush call is added.

#### Keep completion and error handling separate

Register `gpu.onError` for asynchronous validation/execution failures. `frame.done` and
`gpu.settled()` remain resolve-only completion signals; neither they nor a later storage read
prove that the producer succeeded. `settled()` now also waits for queue work already submitted
when called, so it can take longer; later submissions are outside that snapshot. Calls after
observed loss/disposal retain tracked waits without creating a new queue fence.

For a nonconforming queue whose `onSubmittedWorkDone()` throws synchronously, an already-submitted
standalone dispatch now reports one `VGPU-COMPUTE-VALIDATION` through `gpu.onError` at
`<label>.completion` instead of throwing after submission. Conforming queues require no adaptation.

### 4. Handle device loss explicitly and preserve normal teardown

Use the stable readonly `gpu.lost` promise to detect native loss observed while the wrapper is
active. Every running frame loop stops before its handlers run. The next tick no longer emits
an uncaught loss error, so replace global-error-based recovery. Loss does not dispose resources,
notify `gpu.onError` or automatically recreate the device:

```ts illustrative
void gpu.lost.then(() => {
  gpu.dispose();
  return start(); // init(), recreate resources and restart the loop
}).catch((error: unknown) => console.error("GPU restart failed", error));
```

Dispose the old surface/Gpu before configuring its replacement on the same canvas.
`gpu.lost` never rejects, but recovery code can. Factories, `clock()`, `frame()` and `frameLoop()`
now throw `VGPU-DEVICE-LOST` synchronously after observed loss. An already-open manual frame
remains open; `submit()` throws until normal disposal cancels it. Explicit submit error handling
does not change.

Use `gpu.dispose()` for teardown, including inside a frame callback. Direct core
`gpu.device.dispose()`/`destroy()` during a callback now allows implicit-submit errors to escape
instead of swallowing `VGPU-DEVICE-DISPOSED`; a failing loop stops and rethrows.

Normal unmount remains: stop the loop, await `gpu.settled()` if submitted work/deliveries must
finish, then `gpu.dispose()`. Never await `gpu.lost` for teardown. Disposal before vgpu observes
native loss leaves it pending; disposal after observation preserves its resolved value. Disposing
a wrapper from `initFromDevice()` never destroys the borrowed native device. If its owner destroys
that device while the wrapper is active, loss resolves with `reason: "destroyed"`.

Bundles now release abandoned facade retention automatically. Optional, synchronous, idempotent
`bundle.dispose()` drops references immediately without destroying borrowed resources or revoking
a previously saved native bundle handle. Existing recording/replay calls require no migration.
Continue re-recording when captured resource identities, draw counts or render signatures change;
automatic cleanup does not rebuild stale bundles or promise driver-memory release timing.

### 5. Select the intended mouse coordinate space

`canvasMouseTracker` from `@vgpu/render/utils` no longer accepts `normalize`, and `position` is no
longer a tuple. Remove the option and choose `position.normalized` or `position.canvasPixels`:

```ts
import { canvasMouseTracker } from "@vgpu/render/utils";

const canvas = document.querySelector("canvas")!;
const pointer = canvasMouseTracker({ canvas, flipY: true });
const [u, v] = pointer.position.normalized;
const [x, y] = pointer.position.canvasPixels;
pointer.dispose();
```

The former default tuple held CSS-offset pixels; `canvasPixels` holds drawing-buffer pixels.
For CSS/DOM positions, multiply `normalized` by `canvas.clientWidth`/`canvas.clientHeight`
and keep the default `flipY: false` for a top-left origin. Keep `flipY: true` for
a bottom-left origin. When interacting with a lower-resolution offscreen target, convert
normalized coordinates to that target's dimensions rather than reusing canvas pixels.

### 6. Keep optional documentation integrations optional

Scene references, numerical-library examples and Blender skill resources add discovery and
authoring guidance without new runtime dependencies or required application changes. Keep your
project's chosen math library; install an optional one only for your own numerical needs.
Preferred-format examples now describe the existing format contract correctly. The functional
Surface preparation/depth changes are consolidated in step 2; no intermediate migration is needed.

## From release candidates

There are no earlier published `0.6.0` release candidates: this guide accompanies `0.6.0-rc.0`.
No RC-only repair or reversal is required. Users of `0.5.0-rc.0` or `0.5.0-rc.1` first complete
their applicable [0.5.0 RC path](/migrations/0.5.0#from-release-candidates), then apply the
`0.5.0`-origin steps above, retaining already-completed adaptations.

## Verification

1. Typecheck against matching package versions. Find removed scene imports, old `orbit` calls,
   async/unresolved-generic frame callbacks, `normalize` and tuple-valued mouse positions.
2. Exercise object reparenting, explicit camera aspect updates, finite projection bounds, independent
   camera rigs/time steps, zero instances, removals and bridge/mesh destruction. Change a matrix,
   repack its uniform and confirm the next rendered output changes. Verify custom attributes and
   transformed normals on the intended GPU.
3. Compile both automatic and explicitly selected shader entries and compare pixels or compute
   readbacks. Confirm the chosen entry has its inputs and resources. Invalid explicit entries must
   fail with `VGPU-ENTRY-INVALID`.
4. Verify Surface input rejection and an offscreen producer/presentation replacement. Test direct
   surface rendering with default attachments and with depth/MSAA, resize before encoding, rebind
   explicit depth and check stale attachment/bundle handling. Read only current presentation data
   or an owned offscreen texture with explicit mip/region options.
5. On a real GPU, encode multiple operations with distinct managed uniforms and mixed compute/render
   passes; confirm ordering, values and one frame submission. Cancel a frame and confirm its encoded
   work is not submitted. Check live storage, indirect arguments and bundles separately. Await
   compilation; collect `gpu.onError` through completion before assessing execution results.
6. For loss recovery, destroy an externally owned native device wrapped by `initFromDevice()`.
   Confirm `gpu.lost` resolves after loops stop, resources remain undisposed until teardown, and
   recreated resources render on a new GPU. Verify ordinary unmount finishes without awaiting loss.
7. Check pointer alignment when CSS and drawing-buffer dimensions differ, including an upscaled
   offscreen target. For native users, run the installed `vgpu native doctor`, `check`, `build`
   and `verify` and consume the regenerated Swift package on the qualified target platform.

Known RC limitation: a multi-binding `Draw.set({ a, b })` can apply `a` before rejecting `b`;
in that error path a previously recorded bundle may still replay the old `a` reference. Do not
replay the old bundle after such a failure: repair the bindings and explicitly re-record it.
This pre-existing gap is not fixed by automatic bundle retention cleanup.

Complete `ts` blocks participate in snippet typechecking. Blocks marked `ts illustrative`
describe historical or partial application code and are not standalone checked programs.
