# Ownership and lifecycle

One owner controls a `VGPU` context and every live object created from it. View integration normally uses `@MainActor`; offscreen work can use an application-defined actor. Encoding stays synchronous inside that owner while Metal execution and readback continue asynchronously.

> Warning: Native macOS support is a docs-first API proposal. The Swift APIs on this page are not implemented yet.

## Choose one isolation domain

`VGPU`, resources, targets, program instances, frames, and passes intentionally do not conform to `Sendable` and have no global actor annotation. Keep the complete graph in one actor rather than sending individual objects between actors:

```swift
import AppShaders
import VGPUCore
import VGPUMetal
import VGPURender
import VGPUResources

actor RenderWorker {
  private let gpu: VGPU
  private let target: VGPUTarget
  private let effect: VGPUEffect<Gradient>

  init(size: VGPUSize) throws {
    let gpu = try VGPU.metal()
    self.gpu = gpu
    self.target = try gpu.target(
      size: size,
      format: .rgba16Float
    )
    self.effect = try gpu.effect(
      Gradient.self,
      bindings: .init(
        params: .init(
          time: 0,
          size: size.float,
          accent: SIMD3<Float>(0.35, 0.55, 1.0)
        )
      )
    )
  }

  func render() throws {
    try gpu.frame { frame in
      try frame.pass(target: target) { pass in
        try pass.draw(effect)
      }
    }
  }
}
```

Immutable values and independent snapshots such as generated parameter structs, `VGPUSize`, capabilities, error values, and readback results may be `Sendable`.

A view-backed surface follows the same ownership rule. `VGPUSurface` is a backend-neutral handle without global actor isolation; the `gpu.surface(_ view: MTKView)` factory and MetalKit host adapters are `@MainActor` because they touch the borrowed view. In practice, keep that complete view-backed graph on `@MainActor`.

## Fail on overlapping access

Non-`Sendable` prevents ordinary actor crossings, but it cannot detect every unsafe capture. The runtime therefore rejects overlapping public access across different threads or isolation domains with `VGPUError.concurrentAccess` instead of blocking or racing.

The check belongs to the context and is shared by all of its children. Transitive calls in one synchronous stack remain valid, including `gpu.frame`, `frame.pass`, `pass.draw`, and a binding update from the same callback. A call that overlaps from another thread fails immediately. Once the first call returns, the owner may continue using the graph normally.

The implementation only locks long enough to claim or release logical access. It never holds that lock while running application code, encoding a callback, or awaiting Metal. Native completion callbacks, in-flight retains, pipeline cache publication, and error delivery use separate internal synchronization and never re-enter the public gate.

Async methods validate, snapshot their resource generation, and register immutable work while they own access. They release access before their first suspension. Rendering may therefore continue while an already registered readback or pipeline compilation is in flight.

Immutable getters such as capabilities and independently synchronized numeric snapshots do not throw. This exception keeps ordinary reads usable; it does not make the live object graph transferable.

## Keep frame values inside their scopes

The first Swift API exposes callback-scoped frames rather than manually owned command encoders:

```swift
try gpu.frame { frame in
  try frame.pass(target: target) { pass in
    try pass.draw(effect)
  }
}
```

`VGPUFrame` is valid until the outer callback returns. Each `VGPUFramePass` is valid only until its pass callback returns. Swift permits a closure to capture these reference-backed values, so the runtime checks every entry point: later use throws `VGPUError.frameClosed` or `VGPUError.passClosed` before accessing Metal.

A normal return submits the frame once and returns a discardable `VGPUSubmission`, even when the frame encoded no passes. This empty submission preserves queue order and has the same completion contract as any other frame. An explicit `frame.submit()` closes encoding and returns the same stable token that the outer call would return; repeated calls during the callback are idempotent. If the outer callback throws while the frame is open, vgpu cancels it and rethrows the original error, so no token exists. If application code explicitly submits and then throws, submitted work cannot be rolled back and the original error still escapes. The token is observable only if the callback saved the result of `frame.submit()` before throwing.

Nesting is rejected synchronously:

- `gpu.frame` from an active frame throws `.frameReentrant`.
- One-shot draw or dispatch from an active frame throws `.nestedSubmission`.
- `frame.pass` from an active pass throws `.nestedPass`.
- `frame.submit()` from an active pass throws `.framePassActive`.
- Disposing a core context or resource from an active encoding scope throws `.frameActive`.

If another isolation domain attempts one of these operations concurrently, `.concurrentAccess` wins because the runtime cannot safely inspect the active owner's frame state.

## Handle coded errors

`VGPUError` is an immutable, `Sendable`, `LocalizedError`. Its code is an extensible raw-value type rather than a closed enum, allowing opt-in backend and integration modules to add cases without making `VGPUCore` depend on them:

```swift
public struct VGPUErrorCode: RawRepresentable, Hashable, Sendable {
  public let rawValue: String

  public init(rawValue: String) {
    self.rawValue = rawValue
  }

  public static let concurrentAccess = Self(
    rawValue: "VGPU-NATIVE-CONCURRENT-ACCESS"
  )
  public static let contextMismatch = Self(
    rawValue: "VGPU-NATIVE-CONTEXT-MISMATCH"
  )
}
```

Static members still support ordinary switch patterns. Include a default so code also accepts errors added by a newer runtime:

```swift
switch error.code {
case .concurrentAccess:
  fixOwnership()
case .artifactIncompatible:
  rebuildGeneratedPrograms()
default:
  show(error)
}
```

Errors with the same observable meaning reuse JavaScript's code. Native-only ownership or lifecycle checks use the `VGPU-NATIVE-*` namespace:

| Swift member | Raw code | Meaning |
| --- | --- | --- |
| `.gpuDisposed` | `VGPU-GPU-DISPOSED` | New work used a disposed context. |
| `.frameReentrant` | `VGPU-FRAME-REENTRANT` | A frame was opened from an active frame. |
| `.framePassActive` | `VGPU-FRAME-PASS-ACTIVE` | Submission was attempted before the pass returned. |
| `.concurrentAccess` | `VGPU-NATIVE-CONCURRENT-ACCESS` | Public access overlaps another owner. |
| `.contextMismatch` | `VGPU-NATIVE-CONTEXT-MISMATCH` | A wrapper belongs to another context. |
| `.nestedSubmission` | `VGPU-NATIVE-NESTED-SUBMISSION` | A one-shot submission was attempted inside a frame. |
| `.nestedPass` | `VGPU-NATIVE-NESTED-PASS` | A pass was opened from another pass. |
| `.frameClosed` | `VGPU-NATIVE-FRAME-CLOSED` | A scoped frame escaped its callback. |
| `.passClosed` | `VGPU-NATIVE-PASS-CLOSED` | A scoped pass escaped its callback. |
| `.frameActive` | `VGPU-NATIVE-FRAME-ACTIVE` | Disposal was attempted during encoding. |
| `.resourceAlreadyImported` | `VGPU-NATIVE-RESOURCE-ALREADY-IMPORTED` | A Metal resource already has a live wrapper. |
| `.resourceInUse` | `VGPU-NATIVE-RESOURCE-IN-USE` | A closed imported wrapper still has in-flight work. |
| `.resourceImportInvalid` | `VGPU-NATIVE-RESOURCE-IMPORT-INVALID` | A Metal resource cannot satisfy its declared vgpu use. |

Synchronous setup, validation, and encoding failures are thrown to the caller. They are not delivered again through the asynchronous error channel.

## Observe deferred errors

Pipeline validation or command-buffer failure may arrive after a synchronous frame call returned. Subscribe without forcing the context onto a global actor:

```text
public extension VGPU {
  func onError(
    _ handler: @escaping @isolated(any) @Sendable (VGPUError) -> Void
  ) -> @Sendable () -> Void
}
```

`@Sendable` makes unsafe mutable captures a compile-time error. `@isolated(any)` records the handler's actor so delivery returns there. Use an explicit global-actor closure or pass an instance-actor method:

```swift
unsubscribeFromErrors = gpu.onError { @MainActor [weak self] error in
  self?.show(error)
}
```

```swift
import VGPUCore
import VGPUMetal

actor RenderWorker {
  private let gpu: VGPU
  private var unsubscribeFromErrors: (@Sendable () -> Void)?

  init() throws {
    gpu = try VGPU.metal()
  }

  func startObservingErrors() {
    guard unsubscribeFromErrors == nil else { return }
    unsubscribeFromErrors = gpu.onError(receive)
  }

  func stopObservingErrors() {
    unsubscribeFromErrors?()
    unsubscribeFromErrors = nil
  }

  private func receive(_ error: VGPUError) {
    // Runs on this RenderWorker actor.
  }
}
```

Retain the unsubscribe closure until teardown. It is `Sendable`, idempotent, and safe to call from any isolation domain. It invalidates future deliveries and queued invocations that have not started; a handler already running may finish. Each subscription observes publication order without overlapping its own invocations. Different actors may finish handling one error in a different order.

A Metal completion only publishes an immutable error and schedules delivery. It never invokes application code directly or while an internal lock is held. If no handler was active when an error was published, vgpu writes one diagnostic to the platform error log rather than retaining a backlog for future subscribers.

## Wait for submitted work

`VGPUSubmission` is the `Sendable` completion token returned by every successful frame, one-shot effect, one-shot draw, and compute dispatch:

```text
public struct VGPUSubmission: Sendable {
  public func settled(
    isolation: isolated (any Actor)? = #isolation
  ) async
}
```

Every submission-producing entry point is `@discardableResult`:

| Entry point | Result |
| --- | --- |
| `gpu.frame { ... }` | `throws -> VGPUSubmission` after implicit or explicit submit |
| `frame.submit()` | `throws -> VGPUSubmission`, idempotently returning the frame's stable token |
| `effect.draw(to:)` | `throws -> VGPUSubmission` |
| `draw.draw(to:)` | `throws -> VGPUSubmission` |
| `compute.dispatch(...)` | `throws -> VGPUSubmission` |

Returning the frame token preserves the completion semantics of JavaScript `Frame.done`. Returning the same kind of token from one-shot effect, draw, and dispatch calls is an intentional Swift extension; those TypeScript calls currently return `void`.

`submission.settled()` waits without throwing for only that logical submission to finish on the GPU and for every deferred error it causes to be published and delivered to the corresponding handlers. It does not enroll unrelated submissions, compilation, readbacks, or work registered later. Like JavaScript `Frame.done`, this is a completion and timing signal, not an error channel; observe failures with `onError`.

Metal queue order still applies. On a serial queue, including a queue shared with a host renderer, this submission's command buffer cannot finish before commands enqueued ahead of it. The token does not wait for unrelated bookkeeping attached to those earlier commands, such as host readbacks or host error delivery.

The token can cross actors even though the live `VGPU` graph cannot. Its default isolation parameter resumes the caller in the caller's isolation domain.

Do not await every submission in an animation loop. Doing so serializes CPU encoding with GPU execution and removes normal in-flight parallelism. Ignore the discardable token during steady-state rendering and retain it only for a real synchronization boundary, such as a test or a resource handoff.

### Wait for the context snapshot

Use context-wide `settled()` in teardown or when the boundary includes more than one kind of work:

```text
public extension VGPU {
  func settled(
    isolation: isolated (any Actor)? = #isolation
  ) async
}
```

The default argument keeps execution on the caller's actor. `gpu.settled()` snapshots all work already known to the context and waits without throwing for its compilation, readbacks, submissions, native completions, every error they later publish, and the corresponding handler invocations. Work registered after the call is not part of that snapshot. Swift deliberately registers every vgpu frame, one-shot render, and compute submission. This is stronger than the current TypeScript implementation, where a plain one-shot or compute queue completion may be absent unless another tracked fence covers it. Use `submission.settled()` instead when unrelated context work must continue independently.

`settled()` remains valid after disposal so teardown can drain work that the context had already accepted. It is not an error channel; observe deferred failures with `onError`.

## Dispose deterministically

Core contexts and resources expose a throwing, synchronous close:

```text
public extension VGPU {
  func dispose() throws
}

public extension VGPUTarget {
  func dispose() throws
}
```

Disposal is idempotent after a successful close. It prevents new work immediately, invalidates child wrappers, and releases context-owned native objects only after command buffers that already reference them complete. It does not wait for the GPU. Calling `dispose()` concurrently with another public operation throws `.concurrentAccess`; calling it from an active frame or pass throws `.frameActive` instead of partially tearing down an encoder.

Dispose retained children when their lifetime ends, then dispose their context:

```swift
try scene.dispose()
try gpu.dispose()
await gpu.settled()
```

Disposing the context also closes any child still registered with it, so a later child `dispose()` is a no-op. A core object's deinitializer may release thread-safe internal state as a fallback, but explicit disposal remains the deterministic lifecycle boundary.

UI host adapters are different: `VGPUViewRenderer.dispose()` and `@MainActor` `VGPUViewDriver.dispose()` remain non-throwing. The host owns scheduling, stops callbacks first, then performs its internal teardown in a serialized order. A renderer callback that is already running may finish, but no new renderer or error callback starts after host disposal begins.

Call those UI disposal methods explicitly while still on `@MainActor`. A normal deinitializer is nonisolated on the oldest supported Swift toolchains, so it may only release thread-safe internals; it must not clear an `MTKView` delegate, restore view properties, or invoke renderer callbacks. The first release does not rely on Swift 6.2 `isolated deinit` for required cleanup.

The caller remains the native owner of an imported `MTLDevice`, `MTLCommandQueue`, `MTKView`, `MTLBuffer`, or `MTLTexture`. vgpu retains borrowed objects while necessary but never destroys or reconfigures them. Read [Resources and Metal interop](/native/macos/resources) for imported-wrapper handoff.
